# 项目级规则片段

把下面内容粘贴进项目根目录的 AI 规则文件（`AGENTS.md` / `.cursorrules` / `CLAUDE.md` / `.workbuddy/rules` 等），让项目内所有 AI 协作都遵循同一套契约。

```markdown
## AI 协作规则（能力内化 · 知识外置 · AI 增强 · 人在环中）

核心：可以把执行外包给 AI，但不要把思考外包给 AI。

1. 先对齐业务再写代码。业务目的、流程、规则、输入输出、边界未确认前不产出实现。
2. 知识开卷、思考闭卷。API/框架/库/命令/文档/Demo 直接给；
   问题分析、方案设计、关键判断、复杂逻辑、验证交还给我。
3. 默认交付「知识 + 伪代码骨架 + 关键取舍」，不一次性写完整个功能。
4. 不做「AI 说 A 就做 A」的顺从者。主动给反例、风险和被否掉的备选方案。
5. 控制单次输出规模：≤50 行可直接给；51–150 行需声明「要逐行看」；
   151–300 行先拆分；>300 行不交付，改为任务拆解清单 + 第一块。
6. 并发、状态、异常、算法、设计取舍、易错核心逻辑由我自己实现，AI 只做参考与 review。
7. 每次交付结尾附 3–6 条「认知所有权自检」问题，并给出可执行的验证方式。
8. 每次交付结尾说明：改了什么 / 设计取舍 / 需要我判断的点 / 下一小块是什么。
```

---

## 需要区分模式时，追加一段

```markdown
### 模式区分
- 学习模式：不给完整答案，只给提示、检查项、反例；我先给出方案再校对。
- 生产模式：充分开卷，给可用实现与工具建议；但仍不替我做判断与验证。
模式不清时，先问我「这次是想学明白，还是要尽快交付？」
```

## 快速触发短语

用户说下面任意一句时，应切到对应模式：

| 用户说 | 模式 |
| --- | --- |
| 「按我的开发原则来」 | 默认四步流程 |
| 「这次是学习/我要搞懂」 | 学习模式 |
| 「上线/交付/急」 | 生产模式 |
| 「你先给我 API 用法」 | 知识供给（开卷区） |
| 「先给我骨架，别写实现」 | 伪代码骨架 |
| 「帮我 review」 | 交付前 review + 自检 |

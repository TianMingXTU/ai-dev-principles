# 提示词卡片

直接复制使用。每张卡片对应原则里的一条约束。

---

## 卡片 1 · 标准开发开场（默认用这张）

```text
按我的开发原则来，分四步走：

1. 先别写代码。把我的业务需求复述一遍——目的、流程、规则、输入输出、边界，
   有不确定的地方直接问我。
2. 我对齐业务之后，给我这次需要的 API / 框架用法：怎么调用、参数、返回值、
   推荐写法、Demo、容易踩的坑。
3. 把业务逻辑整理成伪代码骨架，标出 [复杂] [风险] [决策] [可复制] 四类节点。
4. 等我确认骨架之后，再进实现。核心实现我自己来，你给参考和 review。
```

---

## 卡片 2 · 只要知识，不要实现（开卷区）

```text
这部分我只要知识，不要实现：
- 涉及哪些 API？
- 怎么调用？参数和返回值是什么？
- 官方推荐写法是什么？
- 有没有最小 Demo？
- 有哪些容易踩的坑？

不要替我决定该不该用这个能力，那是我的判断。
```

---

## 卡片 3 · 学习模式（闭卷训练）

```text
这次是学习模式，训练优先：
- 不要给我完整答案，只给提示和方向。
- 我会先说出我的思路，你再指出漏洞、遗漏的边界条件和反例。
- 我卡住了再给下一个提示，一次一个。
- 允许我慢。
```

---

## 卡片 4 · 生产模式（效率优先，但保留判断权）

```text
这次是生产模式，效率优先：
- 直接给可用的实现和工具建议，不用照顾我。
- 样板代码、重复劳动、测试生成都交给你。
- 但方案设计和关键判断我自己定，你给选项和取舍理由，不要替我拍板。
- 核心逻辑、并发、状态、异常这些标出来，我自己实现。
```

---

## 卡片 5 · 控制输出规模

```text
你这次的输出超过了我能认真审完的量。
请拆成小块：先给我任务拆解清单，然后一次只给一块，
每块结束等我理解并验证之后再继续。

我要能真正 review 完，而不是略读。
```

---

## 卡片 6 · 交付前 review

```text
Review 这段代码。不要只夸，按这个顺序说：
1. 这段解决的是什么业务问题？
2. 关键设计点为什么这么做？有没有更简单的方案？
3. 有哪些边界条件和风险？
4. 哪里最容易出错，出错从哪查？
5. 我该怎么验证它对不对？
6. 有哪些地方是我必须自己搞懂、不能照抄的？
```

---

## 卡片 7 · 先想再问（对抗认知依赖）

```text
我的初步判断是：<在这里写你的方案>
请帮我检查：
- 有没有漏洞？
- 有没有遗漏的边界条件？
- 还有没有其他方案？为什么我没想到？
- 这个设计有什么风险？
```

---

## 卡片 8 · 认知所有权自检

```text
先别继续往下写。围绕刚才这段代码问我几个问题，
检查我是不是真的理解了：

为什么这样设计 / 为什么调这个 API / 参数为什么这么传 /
还有没有其他方案 / 有什么风险 / 出错从哪查 / 我怎么验证它。

我答不上来的地方，你就补讲那一点。
```

---

## 卡片 9 · 纠偏：AI 太顺从了

```text
你太顺着我了。请扮演反方：
给我 2-3 个反对我刚才思路的理由，
指出我方案里最脆弱的地方，
并说出一个你认为更好但我没想到的方案。
```
